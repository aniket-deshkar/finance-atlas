# Finance Atlas Web UI and security review

Reviewed the `dev` source at `71e495d` and the live Firebase site on 23 November 2026. First fix the obstructed mobile controls, navigation focus, and amount masking. The highest security and recovery concern is that a cloud vault switch can leave local documents and chat inaccessible, while the available ledger backups omit them. ## Security findings

The most important risks are loss of access to device data, disclosure through the privacy UI, and reliance on deployment settings to enforce the cloud boundary. This review found no confirmed critical issue in the paths inspected. Live checks verified expected anonymous rejection for two protected API routes. They did not establish authenticated owner behavior or the deployed policy for every service.

### High priority

**S-01. Device records lack a recovery path when the active vault salt changes.** The selected cloud envelope replaces the local envelope, and the new salt becomes the namespace for documents, extracted records, and chat. The earlier records can remain present in IndexedDB while the active workspace loses access to them. Sync conflict recovery saves the ledger envelopes, and the README describes the separate device store. The OpenSpec baseline also explicitly excludes that store from ledger backups. Show this consequence before switching vaults, then add a way to export and restore device records under the original key. Test two fictional vaults with distinct salts, including recovery after a simulated browser reset. [Cloud restore](../../app/page.tsx#L382) · [Device namespace](../../app/page.tsx#L522) · [Conflict recovery](../../app/attention.tsx#L118) · [Vault baseline](../../openspec/specs/vault-recovery/spec.md)

### Medium priority

- **S-02. Amount masking is visual only on reviewed paths.** The live chart label still exposed exact values in privacy mode. Fix the rendered output and accessibility text together. Treat this as a disclosure issue in the unlocked UI. [Chart label](../../app/overview.tsx#L68) · [Masking CSS](../../app/polish.css#L206)
- **S-03. Inline scripts are allowed in the web and desktop CSP.** Hosting includes restrictions for framing, objects, and external connections. Both builds still permit inline JavaScript, which weakens a protection around the app that processes the vault key and decrypted records. This is defense in depth. The review did not establish script injection. For the static web export, evaluate build-generated hashes with a report-only rollout before enforcing a tighter policy. Verify Firebase sign-in, the PDF worker, and desktop separately. [Web CSP](../../firebase.json#L17) · [Tauri CSP](../../src-tauri/tauri.conf.json#L29) · [OWASP CSP guidance](https://cheatsheetseries.owasp.org/cheatsheets/Content_Security_Policy_Cheat_Sheet.html)
- **S-04. Several cloud controls require evidence from the deployed environment.** The API checks revocation and the configured UID. The worker relies on Cloud Run IAM for caller authorization. Rate limiting is registered in Fastify with its local default store. The API buffers authorized snapshot uploads with a limit near 30 MB. Verify worker invoker policy, Cloud Storage IAM, request identity through Hosting, concurrency, and a near-limit transfer in staging. Record the deployed frontend, API, and worker revisions so the evidence can be tied to a release. [API ownership and limits](../../api/app.mjs#L27) · [Snapshot handler](../../api/cloud-routes.mjs#L61) · [Worker deployment](../CLOUD-PILOT.md#L77)
- **S-05. Retention and cleanup need operational controls.** Snapshot ciphertext can be written before the metadata transaction accepts the new head. A conflict can leave an unreferenced object. Old revisions and expired desktop-pairing records also need cleanup. Set and verify a policy that preserves the active head and protected backups while removing expired tickets and unattached objects. [Snapshot store](../../api/cloud-store.mjs#L21) · [Pairing storage](../../api/cloud-store.mjs#L47)

### Lower priority

- **S-06. Show where information goes before users export or request AI.** The Assistant presents a review of question, selected figures, and previous turns, with approval bound to the preview. Make the inclusion of prior turns and the distinction between extracted figures and original documents visible beside Send. Clearly label readable JSON, CSV, and ZIP exports as unencrypted and put the encrypted ledger backup alongside them. [Assistant preview](../../app/assistant.tsx#L249) · [Encrypted export](../../app/records.tsx#L241) · [Readable export](../../app/records.tsx#L324)
- **S-07. Make dependency checks repeatable across the deployed stack.** The production npm audit reported zero known advisories for both the frontend and API lockfiles on the review date. Python dependencies and the native installer were outside that scan. The worker declares Google ADK and GenAI without a full transitive lock. Pin the worker environment and verify container dependencies and base images in CI alongside npm and Cargo. [Worker requirements](../../agent/requirements.txt) · [Worker image](../../agent/Dockerfile) · [API image](../../api/Dockerfile)

## Security boundaries checked

| Boundary | Observed controls and remaining coverage |
| --- | --- |
| Local storage and imports | The vault uses a non-extractable AES-GCM key derived with PBKDF2-SHA256 and 600,000 iterations. Revision checks guard against stale local writes. ZIP import checks expanded size and CRC, PDF reads cap pages and extracted text, and ledger restore verifies record and receipt metadata. Browser-local encryption does not make an unlocked DOM private. [Vault](../../lib/vault.ts#L61) · [ZIP parser](../../lib/files.ts#L189) · [PDF parser](../../lib/documents.ts#L81) |
| Firebase, Fastify, and sync | Protected routes use the owner hook, and Cloud Run initializes revoked-token verification. The cloud store checks the ciphertext digest on download and advances metadata via a Firestore transaction. Checked-in Firestore rules deny direct client reads and writes. Live anonymous checks for the sync head and model catalog returned 401. Owner login and actual infrastructure policies remain unverified. [Owner hook](../../api/app.mjs#L48) · [Token verification](../../api/main.mjs#L72) · [Firestore rules](../../firestore.rules) |
| Desktop | Pairing binds a short-lived one-time code to its verifier and checks state on a loopback listener. Tauri exposes a small command set in the local main window. Reviewed these paths in source and used existing test coverage as reference. Native install and real OAuth pairing remain unverified. [Desktop pairing](../../src-tauri/src/cloud_auth.rs#L7) · [Exchange](../../api/cloud-routes.mjs#L73) · [Tauri capabilities](../../src-tauri/capabilities/default.json) |
| AI and external services | The API restricts models and shapes, reserves an estimated budget, and validates returned reference IDs. The worker receives approved content and relies on its platform IAM boundary. Portfolio quotes use fixed upstream URLs and timeouts. Live provider retention, service permissions, and model calls remain unverified. [AI validation](../../api/assistant.mjs#L24) · [Usage accounting](../../api/assistant.mjs#L49) · [Market proxy](../../api/market.mjs#L22) |
